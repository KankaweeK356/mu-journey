### Network Analytics บน Production (ตรวจเมื่อ 2026-11-23)
- 5 ส่วน (Explorer, MU Recommendation Lab, Signature Trip Designer, Trip Matching, Model Evaluation) เปิดและโหลดได้ ไม่มี error ไม่มี spinner ค้าง ไม่มีคำขอที่ตอบ 404/401/5xx
- **MU Recommendation Lab:** Input = โปรไฟล์ตัวอย่าง (W01, W02, W03, เกิด 2000-03-12) → Network Processing = `/api/trace` ตอบ 200 และ `matches_reference = true` → Output = Top 5 (P001, P002, P014, P019, P029) แสดงครบบนหน้า และตรงกับผลจาก endpoint คำแนะนำของ Production สำหรับ Input เดียวกัน
- **Trip Matching:** ใช้โปรไฟล์จาก Lab → ผลจับคู่ `TRIP_LOVE` ตรงกับ endpoint คำแนะนำของ Production
- ข้อจำกัดของหลักฐาน: การตรวจว่า Trip Matching "ใช้ Input เดียวกับ Lab" ทำโดยดูว่าหน้าแสดงผลได้และผลตรงกับ endpoint เมื่อส่ง Input จาก Lab เท่านั้น ไม่ได้ดักคำขอที่หน้า Matching ส่งเอง (หน้านี้ใช้ผลที่ Lab คำนวณไว้)

### Regression: Network Model, PPR, Top 5 ไม่เปลี่ยน
- `scripts/regression_snapshot.py` รันโปรไฟล์ที่กำหนดตายตัว **342 โปรไฟล์** (ทุกเรื่องเดี่ยว, ทุกคู่, ชุดสามเรื่อง, 4 แบบวันเกิด, 2 แบบข้อจำกัด) บน commit ก่อนแก้ (`286c485`) แล้วบันทึกเป็น `tests/golden/model_outputs_286c485.json`
- `tests/test_regression_model_outputs.py` รันชุดเดียวกันบนโค้ดปัจจุบันและเทียบ: อันดับ, คะแนน PPR (ปัดเศษ 12 ตำแหน่ง), เรื่องที่ตรง, Top 5 ของ service layer, ทริปที่จับคู่ และคะแนนทุกทริป **ตรงกันทุกโปรไฟล์**
- ไฟล์โมเดล (`network_phase1.py`, `input_drive_v2_snapshot.json`, `offline_signature_trip_v1.json`) ไบต์ต่อไบต์เหมือน `286c485` (เทียบหลังปรับ CRLF/LF)
- ข้อจำกัด: ตรวจเฉพาะชุดโปรไฟล์ที่กำหนด ไม่ใช่ทุกโปรไฟล์ที่เป็นไปได้ และเทียบกับ `286c485` ไม่ใช่ทุก commit ก่อนหน้า
