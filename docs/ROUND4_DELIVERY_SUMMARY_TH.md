### Trip Matching: ตรวจอะไรบ้าง
- **Input:** โปรไฟล์ที่หน้าใช้ = Persona ที่กำหนด = คำขอที่ Lab ส่ง (และคำขอที่ปุ่ม "คำนวณ" ของหน้า Matching ส่งเอง) ชิปเรื่องที่เลือกบนหน้า = ชื่อเรื่องของโมเดล
- **ทริปที่เลือก:** ป้าย "ผลลัพธ์", การ์ด "★ ได้รับเลือก" (กรณี C ต้องไม่มีดาวและมีคำอธิบาย `NO_ELIGIBLE_SIGNATURE_TRIP`)
- **ทั้ง 3 ทริป:** Graph Relevance, Wish Coverage, คะแนน (และตัวเลขในสูตร) ที่แสดงบนหน้า เทียบกับค่าของโมเดลหลังจัดรูปแบบแบบเดียวกับหน้า (ทศนิยม 3 ตำแหน่ง / เปอร์เซ็นต์เต็ม) และอยู่ในช่วงปัดเศษของค่าที่ไม่ปัด พร้อมป้ายผ่านเกณฑ์/ไม่ผ่านและเหตุผล
- **ไม่มีค่าสำรอง:** ค่าใดที่หน้าไม่แสดงหรือไม่ตรงกับโมเดล = Fail
- **พิสูจน์ว่าเทสต์ล้มได้จริง:** ผมแก้หน้าเว็บชั่วคราวให้แสดงคะแนนบวก 0.01 เทสต์ล้ม 18 ข้อ (ผ่าน 53/71) แล้วคืนไฟล์เดิม (ไม่มีไฟล์ `matching.js` เปลี่ยนใน commit)

### สถานะหลังส่ง: ตรวจอย่างไร
- **ฝั่งเซิร์ฟเวอร์ (Python):** จำลองการเรียก Apps Script ทุกกรณี (ไม่ตั้งค่า, host ผิด, สำเร็จ, ปฏิเสธ รวมตอบ HTTP 500, เชื่อมต่อไม่ได้ และหมดเวลา) และตรวจว่าแต่ละกรณีมีข้อความไม่ซ้ำกัน ไม่มีคำว่า "ขอบคุณ/บันทึกแล้ว/รับข้อมูลแล้ว" ในกรณีที่ไม่ได้บันทึก และ `retryable` เป็นจริงเฉพาะ `unreachable`
- **ฝั่งหน้าจอ (Edge):** ให้เบราว์เซอร์ตอบแทนเซิร์ฟเวอร์ทีละสถานะ ตรวจว่าหน้าจอไม่ขึ้นสำเร็จเมื่อไม่ได้บันทึก ปุ่มลองใหม่มีเฉพาะ `unreachable` และคำตอบเดิม (ความสนใจ ดาว ข้อความ) ยังอยู่เมื่อกดลองใหม่ ตรวจเนื้อหาคำขอที่ส่ง (`would_use_again`, เวอร์ชันคำถาม, ไม่มีฟิลด์ส่วนบุคคล)
